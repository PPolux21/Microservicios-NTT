# TC-12 — Tokenizar pago y eliminar PAN/CVV del dominio

## Descripción del TC

### Resultado funcional

Las tarjetas se tokenizan mediante `POST /api/payment-methods/tokenize`. El PAN y el CVV sólo forman parte del request y del objeto efímero entregado al gateway fake; las órdenes, los eventos de cocina, los logs y las respuestas no los conservan. Las órdenes API aceptan una referencia `paymentMethodId` y verifican que el método tokenizado pertenezca al usuario autenticado.

### Trabajo solicitado

- Eliminar `ccNumber`, `ccExpiration` y `ccCVV` de la orden y de los eventos.
- Persistir en `PaymentMethod` sólo token, marca, últimos cuatro, expiración no sensible y propietario.
- Tokenizar mediante un puerto `PaymentGateway` y un adaptador fake, sin cifrado casero.
- No mostrar el token completo ni registrar PAN/CVV.
- Crear y probar un script para retirar campos sensibles heredados de MongoDB.
- Permitir crear una orden con una referencia a un método tokenizado del usuario autenticado.

### Restricciones técnicas obligatorias

- CVV no se persiste, reenvía, registra ni incorpora a una orden o evento.
- El token completo no se expone en respuestas ni logs.
- No se usa cifrado propio como sustituto de tokenización.
- Las pruebas usan exclusivamente datos sintéticos.
- Los publishers reactivos se componen sin introducir `block()`, `subscribe()` ni esperas en los flujos de API.

### Criterios de aceptación

- [x] El código productivo no contiene los campos heredados `ccNumber`, `ccCVV` o `ccExpiration`.
- [x] `TacoOrder` y el evento de cocina contienen cero información de pago.
- [x] `PaymentMethod` no contiene PAN/CVV y conserva token, marca, últimos cuatro, expiración segura y usuario.
- [x] Existe `PaymentGateway` y un gateway fake sin cifrado casero.
- [x] `POST /api/payment-methods/tokenize` tokeniza y responde sólo con identificador seguro, `brand` y `last4`.
- [x] El token completo no aparece en respuestas, `toString()` ni logs.
- [x] Una orden se crea con `paymentMethodId` sólo cuando el método pertenece al usuario autenticado.
- [x] `EmailOrderService` valida un método tokenizado sin copiar datos de tarjeta a la orden.
- [x] El adaptador noop registra únicamente el identificador de orden.
- [x] Los datos de desarrollo ya no crean métodos con PAN/CVV.
- [x] La migración elimina los tres campos sensibles heredados y su prueba pasa con datos sintéticos.

### Pruebas mínimas

- `DtoContractTest.shouldNotSerializeSensitiveOrderFields` y `shouldSerializeOnlySafePaymentFields` demuestran serialización segura de órdenes y métodos.
- `PaymentMethodControllerTest.shouldTokenizeSyntheticCardSafely` demuestra el gateway fake, la respuesta segura, la ausencia de PAN/CVV en `PaymentMethod` y la redacción de token/PAN/CVV en `toString()`.

## Cambios de código

### `OrderService.java`

- Se corrigió la autorización para comparar el ID del usuario autenticado con `PaymentMethod.user.id`.
- La orden sólo se guarda y publica después de encontrar un método propio con token no vacío.
- La orden persistida y publicada no recibe token, marca, últimos cuatro, PAN ni CVV.

```java
return paymentMethodRepo
    .findById(command.getPaymentMethodId())
    .filter(method -> user.getId() != null
        && method.getUser() != null
        && user.getId().equals(method.getUser().getId()))
    .filter(method -> method.getPaymentToken() != null
        && !method.getPaymentToken().isEmpty())
    .flatMap(paymentMethod -> {
      TacoOrder order = ApiMapper.toEntity(command);
      order.setUser(user);
      order.setPlacedAt(new Date());
      return repo
          .save(order)
          .flatMap(savedOrder ->
              Mono.fromRunnable(() -> orderMessages.sendOrder(savedOrder))
                  .thenReturn(savedOrder));
    });
```

### `DevelopmentConfig.java`

### `cart.component.ts` y `cart.component.html`

- El formulario envía PAN, expiración y CVV exclusivamente al endpoint de tokenización.
- Con el ID seguro devuelto construye un request de orden separado que contiene `paymentMethodId` y ningún dato de tarjeta.
- PAN y CVV se limpian del modelo después de tokenizar.

```typescript
const tokenizationRequest = {
  cardNumber: this.model.cardNumber,
  expiration: this.model.expiration,
  cvv: this.model.cvv
};

this.httpClient.post<any>(
    'http://localhost:8080/api/payment-methods/tokenize',
    tokenizationRequest).subscribe(paymentMethod => {
  const orderRequest = {
    paymentMethodId: paymentMethod.id,
    tacos: this.model.tacos
  };
  this.model.cardNumber = '';
  this.model.cvv = '';
});
```

### `tc12-remove-sensitive-payment-data.js` y `tc12-remove-sensitive-payment-data.test.js`

- La migración recorre las colecciones y aplica `$unset` a `ccNumber`, `ccCVV` y `ccExpiration` donde existan.
- La prueba usa un documento completamente sintético y falla si sobrevive cualquiera de los campos.

```javascript
const sensitiveFields = {
  ccNumber: "",
  ccCVV: "",
  ccExpiration: ""
};

db.getCollectionNames().forEach(collectionName => {
  const collection = db.getCollection(collectionName);
  const query = {
    $or: [
      { ccNumber: { $exists: true } },
      { ccCVV: { $exists: true } },
      { ccExpiration: { $exists: true } }
    ]
  };
  collection.updateMany(query, { $unset: sensitiveFields });
});
```

## Cambios que no se realizaron

No se implementaron precios, disponibilidad, stock, cupones, cálculo de totales, nuevos estados, contrato unificado de eventos, selección dinámica de broker, outbox, reintentos, DLQ ni idempotencia. Esas funciones pertenecen a TC-13 o posteriores. Tampoco se cambió la arquitectura de repositorios ni se añadió un proveedor de pagos real.

## Resultado

TC-12 queda implementado: el flujo tokeniza datos sintéticos, persiste sólo una referencia/token seguro con metadatos permitidos, valida al propietario, crea y publica órdenes sin datos de pago, no expone el token y dispone de una migración probada para datos heredados. Las pruebas enfocadas de TC-12 y la compilación Angular pasan. La suite completa conserva fallos preexistentes de TC-09/TC-11 ajenos a este reto, documentados en el reporte de ejecución.
