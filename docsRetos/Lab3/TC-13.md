# TC-13 — Catálogo con precio, disponibilidad y stock

## Descripción del TC

### Resultado funcional

El catálogo de ingredientes ahora conserva un precio monetario con dos decimales, disponibilidad comercial, existencias, nivel de reorden y una versión para control de concurrencia. La consulta pública expone únicamente el precio y la disponibilidad junto con los datos básicos del ingrediente. Las operaciones administrativas permiten actualizar explícitamente el catálogo y ajustar el stock sin aceptar resultados negativos.

### Trabajo solicitado

- Incorporar precio unitario, disponibilidad, stock, nivel de reorden y versión al ingrediente.
- Representar el precio con `BigDecimal` y validar que no sea negativo.
- Mantener el stock como entero no negativo y asegurar coherencia entre disponibilidad y existencias.
- Permitir que únicamente un administrador modifique precio, disponibilidad o stock.
- Exponer el catálogo público sin metadatos operativos innecesarios.
- Detectar versiones obsoletas y conflictos de concurrencia.
- Inicializar datos de desarrollo coherentes.
- Probar redondeo monetario, validación negativa, control de concurrencia y autorización administrativa.

### Restricciones técnicas obligatorias

- El precio se almacena como `BigDecimal`, nunca como `double`.
- El stock no puede quedar negativo.
- La disponibilidad activa exige existencias mayores que cero; una disponibilidad inactiva puede conservar stock para permitir una pausa comercial.
- Las mutaciones administrativas requieren el rol `ADMIN`.
- Las actualizaciones usan la versión esperada y `@Version` de Spring Data MongoDB.
- Los flujos permanecen reactivos y no incorporan `block()`, `subscribe()` ni esperas arbitrarias.
- No se introducen reservas de inventario, totales de orden ni funcionalidades correspondientes a TC-14 o retos posteriores.

### Criterios de aceptación

- [x] `Ingredient` conserva `unitPrice`, `available`, `stockOnHand`, `reorderLevel` y una propiedad con `@Version`.
- [x] El precio se maneja con `BigDecimal`, se redondea a dos decimales y no admite valores negativos.
- [x] El stock y el nivel de reorden no admiten valores negativos.
- [x] Un ingrediente disponible requiere stock mayor que cero.
- [x] `GET /api/ingredients` muestra precio y disponibilidad sin exponer stock, nivel de reorden ni versión.

- [x] `POST /api/admin/ingredients/{id}/stock-adjustments` aplica ajustes sin permitir stock resultante negativo.
- [x] Los usuarios sin rol `ADMIN` reciben un error de autorización al intentar mutaciones operativas.
- [x] Las versiones esperadas obsoletas y los fallos de bloqueo optimista se traducen a conflicto HTTP 409.
- [x] Los datos de desarrollo comienzan con precios, disponibilidad y existencias coherentes.

## Cambios de código

### `Ingredient.java`

Se añadieron los campos del catálogo y sus validaciones. `unitPrice` normaliza su escala a dos decimales con `RoundingMode.HALF_UP`; `stockOnHand` y `reorderLevel` son enteros no negativos; `version` usa `@Version`. La validación de estado impide marcar como disponible un ingrediente sin existencias. Se conservó el constructor anterior para no romper los usos existentes.

```java
@NotNull
@DecimalMin("0.00")
private BigDecimal unitPrice = BigDecimal.ZERO.setScale(2);

private boolean available;

@Min(0)
private int stockOnHand;

@Min(0)
private int reorderLevel;

@Version
private Long version;

public void setUnitPrice(BigDecimal unitPrice) {
  this.unitPrice = unitPrice != null
      ? unitPrice.setScale(2,RoundingMode.HALF_UP)
      : null;
}

@AssertTrue(message="available ingredients must have stock")
@JsonIgnore
public boolean isCatalogStateValid() {
  return !available || stockOnHand > 0;
}
```

### `IngredientController.java`

Se conservaron las rutas existentes bajo `/api/ingredients` y se incorporaron las dos operaciones administrativas requeridas. Ambas obtienen el ingrediente reactivamente, validan el rol, comparan la versión esperada, validan el estado resultante y guardan mediante el repositorio reactivo. Un ajuste que deja stock en cero desactiva la disponibilidad; un aumento de stock no reactiva automáticamente un ingrediente pausado. Los errores de bloqueo optimista se convierten en 409 mediante el manejo uniforme existente.

La actualización general existente ahora modifica sólo nombre y tipo, con lo cual no borra accidentalmente el catálogo ni la versión del ingrediente.

```java
@PatchMapping("/admin/ingredients/{id}/catalog")
public Mono<IngredientAdminResponse> updateCatalog(
    @PathVariable String id,
    @Valid @RequestBody IngredientCatalogUpdateRequest request,
    Authentication authentication) {

  if (!isAdmin(authentication)) {
    return Mono.error(
        ApiException.forbidden("ADMIN_REQUIRED","Only ADMIN can modify the catalog."));
  }

  return repo.findById(id)
      .flatMap(ingredient -> {
        verifyVersion(ingredient,request.getExpectedVersion());
        if (request.getUnitPrice() != null) {
          ingredient.setUnitPrice(request.getUnitPrice());
        }
        if (request.getAvailable() != null) {
          ingredient.setAvailable(request.getAvailable());
        }
        verifyCatalogState(ingredient);
        return repo.save(ingredient);
      })
      .onErrorMap(OptimisticLockingFailureException.class,
          error -> ApiException.conflict(
              "INGREDIENT_VERSION_CONFLICT",
              "Ingredient was modified by another request."))
      .map(ApiMapper::toAdminResponse);
}
```

El ajuste de stock calcula primero el resultado en `long`, rechaza negativos y desactiva automáticamente un ingrediente que llega a cero:

```java
long adjustedStock = (long) ingredient.getStockOnHand()
    + request.getQuantity();

if (adjustedStock < 0 || adjustedStock > Integer.MAX_VALUE) {
  return Mono.error(
      ApiException.unprocessable(
          "INVALID_STOCK_ADJUSTMENT",
          "Stock adjustment must produce a non-negative integer."));
}

ingredient.setStockOnHand((int) adjustedStock);
if (adjustedStock == 0) {
  ingredient.setAvailable(false);
}
```

### `DevelopmentConfig.java`

Los diez ingredientes de desarrollo se inicializan con precios `BigDecimal`, stock positivo, nivel de reorden y disponibilidad coherente.

```java
Ingredient flourTortilla = saveAnIngredient(
    "FLTO", "Flour Tortilla", Type.WRAP, "0.75", 120, 20);
Ingredient groundBeef = saveAnIngredient(
    "GRBF", "Ground Beef", Type.PROTEIN, "2.25", 80, 15);

private Ingredient saveAnIngredient(String id,String name,Type type,
    String unitPrice,int stockOnHand,int reorderLevel) {
  Ingredient ingredient = new Ingredient(
      id,name,type,new BigDecimal(unitPrice),true,stockOnHand,reorderLevel);
  repo.save(ingredient).subscribe();
  return ingredient;
}
```

## Cambios que no se realizaron

- No se añadieron reservas o liberaciones de inventario al crear órdenes.
