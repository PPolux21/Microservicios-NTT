# TC-01 Actualizar un ingrediente sin perder el publisher

## Requisitos del proyecto

### Trabajo solicitado

- Cambiar el endpoint PUT para retornar `Mono<ResponseEntity<Ingredient>>` o un contrato reactivo equivalente.
- Validar que el identificador de la ruta y el cuerpo sean consistentes; no confiar silenciosamente en uno de ellos.
- Devolver 200 con la entidad actualizada, 404 cuando el ingrediente no existe y 400 ante un ID inconsistente.
- Evitar cualquier llamada manual a `subscribe()`.

### Restricciones técnidas obligatorias

- La escritura debe formar parte de la cadena retornada al framework.
- La existencia se comprueba antes de guardar; no crear accidentalmente un registro con PUT.
- El endpoint debe conservar `application/json` y no filtrar excepciones internas.

### Criterios de aceptación

+ [ ] Una actualización válida cambia el dato consultado después por GET.
+ [x] Un ID inexistente no crea un documento.
+ [x] Un ID del cuerpo distinto al de la ruta genera error de cliente.
+ [x] El código no contiene `subscribe()`, `block()` ni `void` en esta operación.

### Pruebas mínimas

- Prueba de controlador para 200/400/404.
- Prueba con StepVerifier que confirme emisión y finalización.
- Regresión: verificar que `repo.save()` sí sea invocado al suscribirse.

> **Pregunta para defender la solución**
>
> ¿Por qué una llamada a `repo.save()` puede “verse correcta” y aun así no ejecutar I/O?

## Modificaciones y su cuplimiento de los retos

Se modificaron los archivos [`IngredientController.java`](../../tacocloud/tacocloud-api/src/main/java/tacos/web/api/IngredientController.java) y el archivo de pruebas [`TacoControllerTest.java`](../../tacocloud/tacocloud-api/src/test/java/tacos/web/api/TacoControllerTest.java) para poder completar con éxito este reto.

### `IngredientController.java`

Empezando por el [`IngredientController.java`](../../tacocloud/tacocloud-api/src/main/java/tacos/web/api/IngredientController.java) en donde se tuvo que modificar gran medida el método de la api `updateIngredient()` tal y como se muestra a continuación:

``` java
  // Antes de la modificación
  @PutMapping("/{id}")
  public void updateIngredient(@PathVariable String id, @RequestBody Ingredient ingredient) {
    if (!ingredient.getId().equals(id)) {
      throw new IllegalStateException("Given ingredient's ID doesn't match the ID in the path.");
    }
    repo.save(ingredient);
  }

  // Después de la modificación
  @PutMapping("/{id}")
  public Mono<ResponseEntity<Ingredient>> updateIngredient(@PathVariable String id, @RequestBody Ingredient ingredient) {
    if (!ingredient.getId().equals(id)) {
      return Mono.just(ResponseEntity.badRequest().build()); // 400 Bad Request
    }

    return repo.findById(id)
      .flatMap(repoFound -> {
        return repo.save(ingredient)
          .map(savedIngredient -> ResponseEntity.ok(savedIngredient)); // 200 OK
      })
      .defaultIfEmpty(ResponseEntity.notFound().build()); // 404 Not Found
  }
```

De esta forma se cumple con los solicitado:
- **El cambio del tipo de retorno en el método:** cambio de `void` a `Mono<ResponseEntity<Ingredient>>` en el tipo de retorno del método.
- **Validación del identificador para la consistencia de los datos:** ya estaba implementado solo se ajustó el retorno al encontrar inconsistencia.
- **Manejo de los códigos http:** haciendo uso de `ResponseEntiy` para el manejo de los códigos http, indicados en el código cuando se devuelve cada uno.

### `TacoControllerTest.java`

Continuando con el archivo de pruebas [`IngredientControllerTest.java`](../../tacocloud/tacocloud-api/src/test/java/tacos/web/api/TacoControllerTest.java), se implementó una serie de métodos de pruebas unitarias reactivas para validar los distintos escenarios del método `updateIngredient()`. A continuación se muestra el código implementado:

```java
  // Pruebas con WebTestClient para el método updateIngredient
  // 400 Bad Request test
  @Test 
  public void shouldReturnBadRequestWhenIdsMismatch() {
    IngredientRepository ingredientRepo = Mockito.mock(IngredientRepository.class);
    Ingredient testIngredient = new Ingredient("1", "Ingredient 1", Type.WRAP);

    WebTestClient testClient = WebTestClient.bindToController(
        new IngredientController(ingredientRepo)).build();

    testClient.put()
        .uri("/api/ingredients/2")
        .contentType(MediaType.APPLICATION_JSON)
        .bodyValue(testIngredient)
      .exchange()
      .expectStatus().isBadRequest();
  }

  // 404 Not Found test
  @Test 
  public void shouldReturnNotFoundWhenIngredientDoesNotExist() {
    IngredientRepository ingredientRepo = Mockito.mock(IngredientRepository.class);
    Ingredient testIngredient = new Ingredient("1", "Ingredient 1", Type.WRAP);

    when(ingredientRepo.findById(any(String.class))).thenReturn(Mono.empty());

    WebTestClient testClient = WebTestClient.bindToController(
        new IngredientController(ingredientRepo)).build();

    testClient.put()
        .uri("/api/ingredients/1")
        .contentType(MediaType.APPLICATION_JSON)
        .bodyValue(testIngredient)
      .exchange()
      .expectStatus().isNotFound();
  }

  // 200 OK test
  @Test 
  public void shouldUpdateIngredientAndReturnOk() {
    IngredientRepository ingredientRepo = Mockito.mock(IngredientRepository.class);
    Ingredient testIngredient = new Ingredient("1", "Ingredient 1", Type.WRAP);

    when(ingredientRepo.findById(any(String.class))).thenReturn(Mono.just(testIngredient));
    when(ingredientRepo.save(any(Ingredient.class))).thenReturn(Mono.just(testIngredient));

    WebTestClient testClient = WebTestClient.bindToController(
        new IngredientController(ingredientRepo)).build();

    testClient.put()
        .uri("/api/ingredients/1")
        .contentType(MediaType.APPLICATION_JSON)
        .bodyValue(testIngredient)
      .exchange()
      .expectStatus().isOk();
  }

  // StepVerifier test 
  @Test 
  public void shouldUpdateIngredientAndVerify(){
    IngredientRepository ingredientRepo = Mockito.mock(IngredientRepository.class);
    Ingredient testIngredient = new Ingredient("1", "Ingredient 1", Type.WRAP);

    when(ingredientRepo.findById(any(String.class))).thenReturn(Mono.just(testIngredient));
    when(ingredientRepo.save(any(Ingredient.class))).thenReturn(Mono.just(testIngredient));

    IngredientController controller = new IngredientController(ingredientRepo);

    Mono<ResponseEntity<Ingredient>> resultado = controller.updateIngredient("1", testIngredient);

    StepVerifier.create(resultado)
        .expectNextMatches(response -> response.getStatusCode().is2xxSuccessful())
        .verifyComplete();

    Mockito.verify(ingredientRepo).save(testIngredient);
  }
```

De esta forma se cumple con lo solicitado en los criterios de aceptación y restricciones:

- **Prueba de controlador para 200/400/404:** Se crearon tres escenarios separados usando `WebTestClient` para simular peticiones HTTP garantizando que se manejen los estados `isOk()`, `isBadRequest()` e `isNotFound()`.
- **Prueba con StepVerifier:** Se validó directamente el método asegurando la emisión correcta de la respuesta y su conclusión asíncrona mediante `verifyComplete()`.
- **Regresión y verificación de invocación:** Haciendo uso de `Mockito.verify()`, se corroboró de manera estricta que la operación `repo.save()` sí es llamada dentro de la cadena reactiva al momento de suscribirse, garantizando que no existan operaciones de escritura huérfanas o bloqueantes.
- **Simulación de flujos vacíos:** Se garantizó que un ID inexistente no cree documentos accidentales simulando correctamente un `Mono.empty()` en la base de datos durante las pruebas.
